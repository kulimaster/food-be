# Business Description

Status: **living document** — grows as we work through domain decisions together.
Decisions marked *(Proposed)* are default assumptions, not yet confirmed.

## Overview

**Food** is a single-user meal-planning and nutrition-tracking app. A user tracks daily
calorie/macro intake against a personal target, builds recipes from ingredients, logs
meals, plans a week of meals ahead, and generates a shopping list from that plan.

## Users & onboarding

- A user has a profile: weight, height, age, sex, activity level, goal (lose / maintain
  / gain weight), and **timezone**.
- On onboarding (and whenever the profile changes), the app calculates a daily macro
  target:
  1. **BMR** (Basal Metabolic Rate) via the **Mifflin-St Jeor** formula.
  2. **TDEE** (Total Daily Energy Expenditure) = BMR × activity multiplier.
  3. Calorie target = TDEE adjusted for goal (deficit for weight loss, surplus for
     weight gain, unchanged for maintenance).
  4. Macros (protein / carbs / fat / fiber) are derived from the calorie target using
     standard ratios *(exact ratios — Proposed, TBD)*.
- The user **can manually override** the calculated target (e.g. following a
  nutritionist's own numbers) — the calculated value is a suggestion, not a hard rule.
- Accounts are **single-user** for now — no family/shared-plan accounts.

## Ingredients

- For now, the ingredient database is **entirely user-entered** — no external/barcode
  API integration yet (barcode scanning is deferred until this exists).
- Custom ingredients added by any user are **shared globally** — visible and usable by
  all users, not private to the creator. *(Note: since there's no moderation step yet,
  data quality/duplicates are a known risk to revisit later.)*
- Each ingredient has: name, nutrition per 100g (calories, protein, carbs, fat, fiber),
  and tags (e.g. High Protein, Vegan, Basic) for search/filtering.

## Recipes

- A recipe combines multiple ingredients, each with a quantity, plus a servings count.
- Total and per-serving macros are calculated automatically from the ingredient
  quantities — never entered manually.
- A recipe can be saved as a **favorite** for one-tap logging later.

## Meal logging

- A logged meal entry (`MealLog`) belongs to a date + meal slot (breakfast / lunch /
  dinner / snack).
- An entry can be created from:
  - a **raw ingredient** directly (ingredient + quantity), **or**
  - a **recipe** (a portion/serving of a saved recipe), **or**
  - a **favorite meal** (one-tap logging of a previously saved recipe/ingredient combo).

## Activity logging

- A user can log sport/exercise activities per day (`ActivityLog`): activity type,
  duration, and calories burned.
- Calories burned are **entered manually** by the user for now (no MET-formula
  estimation yet — that can be added later without changing the log's shape).
- Logged activity **increases that day's calorie target** ("eat back" burned calories),
  the same way popular fitness-tracking apps handle exercise — it does not just sit
  there as informational-only data.

## Dashboard

- The dashboard shows macro progress (calories, protein, carbs, fat, fiber) against
  target for a **selected day** — defaulting to today, but the user can navigate to
  yesterday and other past days to review history, not just "today only."
- The calorie target shown includes any adjustment from that day's logged activities
  (see Activity logging above).
- "Day" boundaries are defined by the **user's timezone**, not server/UTC time — a meal
  logged at 11pm local time belongs to that local day, not the next UTC day.

## Weekly planner & shopping list

- The planner assigns **recipes and/or raw ingredients** to specific calendar days and
  meal slots — mirroring meal logging exactly (a planned entry is either a recipe
  portion or a raw ingredient+quantity).
- The core purpose: plan a day's (or week's) full nutrition in advance — typically all
  at once (e.g. "on Sunday, plan the whole week") — and see whether the **planned**
  macros for a day hit that day's target, the same way logged meals are checked
  **after** the fact. This is what makes the planner more than a calendar of recipes.
- The shopping list is generated by aggregating the ingredients (and quantities) of all
  planned recipes and standalone ingredients across a selected date range, scaled by
  servings where applicable.
- Single-user scope: no sharing a plan or shopping list with others for now.
